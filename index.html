Dimensional Modeling Techniques

Kimball Methodology
⬡
Dimensional Modeling
Structuring analytical data into facts and dimensions following Kimball's four-step process.
⬡
Star Schema
Building denormalized schemas with a central fact table surrounded by descriptive dimension tables.
⬡
Fact Table Design
Designing fact tables to capture business events with additive, semi-additive, and non-additive measures.
⬡
Dimension Table Design
Creating descriptive context tables with surrogate keys, hierarchies, and attributes for slicing and filtering.
⬡
Surrogate Keys
Using system-generated keys to decouple warehouse identity from source system natural keys.
⬡
Slowly Changing Dimensions (SCD)
Handling dimension attribute changes over time using Type 1 (overwrite), Type 2 (versioned rows), and Type 3 strategies.
⬡
Conformed Dimensions
Designing shared dimensions used consistently across multiple fact tables and business processes.

Fact Table Design Patterns

Selecting the appropriate fact table type based on the business process and the analytical questions being asked.

Pattern

Transaction Fact Tables

One row per discrete business event. Captures individual transactions at the most granular level — ideal for detailed event analysis and drill-down reporting.

Example: Each sales order line, each payment, each click event
Pattern

Periodic Snapshot Fact Tables

One row per measurement period. Captures cumulative or point-in-time metrics at regular intervals — suited for trend analysis and performance monitoring.

Example: Monthly account balance, daily inventory level, weekly pipeline status
Pattern

Accumulating Snapshot Fact Tables

One row per process instance, updated as it progresses through milestones. Tracks lifecycle durations and stage-to-stage lag analysis.

Example: Order fulfillment pipeline, loan application lifecycle, support ticket resolution
